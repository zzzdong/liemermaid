## 1. 两条管线架构

### 新管线（目标形态）

```
AST → extract → Unigraph(UG) → measure → UG' → engine → (Geograph + StyleIntent)
        → materialize → SceneGraph → paint → lievisual::Scene
```

- **extract**（`src/builder/extract/`）：AST → 统一拓扑图 `Unigraph`，不碰坐标/尺寸/颜色。
- **measure**（`src/builder/measure/`）：测量文本尺寸写回 UG。
- **engine**（`src/builder/layout/engine.rs`）：分层 → 坐标分配 → 端口解析 → 边路由 → 容器包围盒。
- **materialize**（`src/builder/materialize/`）：唯一消费 theme 常量的视觉决策点，产出 `SceneGraph`。
- **paint**（`src/builder/paint/`）：零分支纯翻译 `SceneGraph` → `lievisual::Scene`。

分派入口：`src/builder/mod.rs::build_diagram_with_config`，`extract::run` 成功则走新管线，失败则降级旧管线。

### 旧管线（待淘汰）


- `src/builder/render/mod.rs::render_placed`（渲染分派）

## 10. 新管线设计

### 10.1 三层 IR + 两层视觉图

数据在管线中经历五次形态变换，核心是"**拓扑 → 几何 → 视觉**"的逐步具象，每层严守一条纪律：

| 阶段 | 产物 | 类型 | 含坐标 | 含颜色 | 职责纪律 |
|---|---|---|---|---|---|
| extract | `Unigraph`(UG) | `ir/unigraph.rs` | ❌ | ❌ | AST 唯一出口，不碰坐标/尺寸/颜色 |
| measure | UG' | 同 UG | ❌ | ❌ | 仅做文本测量，`LabelSpec`→`MeasuredLabel` |
| engine | `Geograph`(GG) | `ir/geograph.rs` | ✅ | ❌ | 仅做几何：坐标/尺寸/路由已定，仍无颜色 |
| materialize | `SceneGraph` | `ir/scenegraph.rs` | ✅ | ✅ | 唯一消费 theme 常量的视觉决策点 |
| paint | `lievisual::Scene` | 外部库 | ✅ | ✅ | 零分支纯翻译，不接收 `&Diagram`/`&Theme` |

**关键设计**：`extract` 产出 UG 后可被 drop，GG 与 UG 解耦——`engine` 结束时把"几何 + 样式意图(`StyleIntent`)"分离，`materialize`/`paint` 不持有 UG 引用，结构上杜绝回查 AST。

### 10.2 图家族分派（`GraphFamily`）

UG 携带 `family` 字段，决定 `engine` 走哪套布局/路由策略：

| Family | 覆盖图 | 布局策略 | 状态 |
|---|---|---|---|
| `Directed` | flowchart / state | Sugiyama 分层 + barycenter + 正交/样条路由 | ✅ |
| `Grid` | class / er | BFS 网格分层 + 关系路由 | ✅ |
| `Linear` | mindmap / timeline | 线性排布 | ⏳ 预留 |
| `Sequence` | sequence | 泳道 + 消息时序 | ⏳ 预留 |
| `Radial` | pie / quadrant | 极坐标 | ⏳ 预留 |
| `Hierarchy` | gitgraph / gantt / sankey | 层级 / 时间轴 | ⏳ 预留 |

> `extract` 透传 `direction`（TB/TD/BT/LR/RL）；`engine` 据此旋转坐标轴，与 family 无关。

### 10.3 关键 IR 类型

- **`NodeDetail`**（`ir/common.rs`）：结构化节点详情。`None`=普通单栏节点；`Class { annotation, attrs, methods }`=UML 类框三栏；`Entity { attrs }`=ER 实体框两栏。
- **`EdgeKind`**：边语义类别（`Flow`/`StateTransition`/`ClassExtends`/`ClassComposition`/…），驱动 materialize 选线型/箭头表。
- **`RoutingHint`**：`Orthogonal`（曼哈顿折线）/ `Spline`（贝塞尔）。flowchart 默认 Spline，state 默认 Orthogonal。
- **`LineKind`**：`Solid`/`Dotted`/`Thick`/`Invisible`，来自箭头语法（`-->`/`-.->`/`==>`/`~~~`）。
- **`ContainerKind`**：`Subgraph`/`StateComposite`/`Lifeline`/`ClassBox`/`Slice`。
- **`RoutePath`**（`ir/geograph.rs`）：连续 `RouteSegment`（`Line` 或 `CubicBezier`）序列，供 materialize/paint 按段画 `<line>` 或 `<path d="M..C..">`。

## 11. 布局算法

### 11.1 Directed 分层（`layout/directed.rs`）

三步：**反馈边检测 → 最长路径松弛分层 → 交叉减少**。

1. **反馈边检测 `detect_back_edges`**：迭代 DFS 三色标记（0 未访问/1 在栈/2 已结束），指向"当前 DFS 栈中祖先"的边记为 back edge。显式栈模拟递归，避免大图栈溢出。
2. **最长路径松弛 `assign_layers`**：层号 = 沿非 back edge 的最大前驱层 + 1，跳过 back edge（避免环把层号推高）；层号上限 `n-1`，`guard` 迭代上限 `n+1` 兜底。
3. **交叉减少 `minimize_crossings`**（`layout/crossing.rs`）：barycenter（重心）启发式，偶数轮自上而下、奇数轮自下而上，共 4 轮；每轮**动态**重算邻居当前位置（非静态邻接表），同分按插入序 tie-break 保证确定性。
4. **方向反转**：`direction` 为 `BT`/`RL` 时整体 `reverse()` 层序。

### 11.2 Grid 分层（`engine.rs::grid_layers`）

class/er 用 BFS 分层替代 Sugiyama：入度 0 节点为第 0 层，逐层推进；**层内保持源码序**（class 图按声明顺序排布），不做交叉减少；全成环（无入度 0）退化为单层。

### 11.3 坐标分配（`engine.rs::run`）

- **双轴模型**：主轴 = 层推进方向（TB 垂直 / LR 水平）；同层轴 = 节点展开方向。
- **层厚**（cross）= 层内节点在主轴方向的尺寸最大值；**层长**（main）= 同层轴尺寸累加 + `NODE_GAP`。
- **层间标签预留**：相邻两层间存在带标签边时额外 `EDGE_LABEL_GAP`，避免标签压节点。
- **居中**：主轴起点 = `-total_main / 2`，整体居中；同层内节点按 `NODE_GAP` 间距居中展开。
- 端口解析 `resolve_ports` 由 center + size 算四向端口；再据 `ShapeKind` 做形状感知边界投影。

### 11.4 容器包围盒（`engine.rs::compute_containers`）

据 `subgraphs[].member_ids` 找到已布局成员节点，计算 min/max 包围盒，四周 `PAD` + 顶部 `TITLE_H` 留白生成容器框。**容器不参与分层**，仅事后"包住"成员节点。

## 12. 碰撞检测与避让算法

### 12.1 碰撞原语（`layout/spatial.rs`）

- **`segment_intersects_segment`**：标准跨立实验 + 共线重叠判定。严格异号叉积 = 内部相交；端点叉积为 0（共线/端点接触）时用 `point_on_segment`（含 bbox 容差）判真接触。**修正旧实现 `d1*d2<=0 && d3*d4<=0` 把共线但分离的两线段误判为相交的假阳性**（阶段 0.1）。
- **`segment_intersects_rect`**：端点在内，或与矩形四边任一相交。

### 12.2 路由总控（`layout/route.rs::route_edges`）

为每条边分类生成 `Plan`，再逐边路由：

| Plan | 触发条件 | 策略 |
|---|---|---|
| `SelfLoop` | source == target | 节点右侧外凸环（单段贝塞尔） |
| `Mutual` | u↔v 双向同时存在 | 小偏移 + 轻微外弓的平行弧线 |
| `BackBow` | 回边且无阻挡 | 侧向 U 形贝塞尔 |
| `BackChannel` | 回边且有阻挡 | 侧边通道绕行（圆角折线） |
| `Normal` | 其余 | Spline / Orthogonal |

### 12.3 端口选择与分散

- **`pick_port`**：优先沿布局主轴出线（TB→Top/Bottom，LR→Left/Right），当对端明显在侧方时（`SIDE_BIAS=2.5` 判据）切到侧面端口，避免同层横向相邻点被迫绕一大圈。
- **`rank_slots`**：同一节点同一端口的多条边，按对端在该端口轴向的投影排序 → 分配槽位 `(idx, total)`，保证 fan-out/fan-in 空间顺序一致、不打结。
- **`port_point_at`**：槽位沿节点边居中对称分散，`spacing` clamp 到 `[PORT_MIN_SPACING, span×0.4]` 且不贴角；Diamond/Circle 形状按边界投影（端口永远落在形状边界上，不悬空）。

### 12.4 Spline 路由（`spline_route` + `spline_route_safe`）

- 单段三次贝塞尔：控制点沿端口法向延伸 `arc`，并沿垂直流向偏置 1/4 形成扇形展开。
- **单调性约束**：`arc` 只取两端口净间距 `gap` 的一半且 `arc <= gap`，保证曲线在主轴单调，同一源的多条出边**互不交叉**（旧实现按 `max(|dx|,|dy|)` 取弧度会甩过目标行形成 S 形回绕）。
- **节点回避**：先按朴素贝塞尔 `sample_path`（32 等分）采样检测；若穿过非端点节点，退化为「stub + 侧边通道 + 圆角折线」绕行。

### 12.5 Orthogonal 路由（`orthogonal_route`）

stub + 主干曼哈顿折线。主干位置（垂直主轴=共享 x，水平主轴=共享 y）从两 stub 端点中点出发，沿主轴法向双向步进（`OFFSET_STEP=12`，最多 8 次），取**冲突段数最少、偏移最小**的落点，处理长边跨层（主干初始位置落在中间层节点内）的情况。

### 12.6 回边通道规划（`plan_back_channel` + `settle_channel`）

回边（source 在主轴下游）检测两中心间阻挡带（`BAND_PAD` 外扩）是否命中中间节点：

1. 命中 → `settle_channel` 从命中节点外侧逐个让开挡路节点（`CHANNEL_MARGIN=16`）。
2. `try_channel_side` 再避开**已占用通道**：同坐标且跨度重叠时沿侧向 `CH_STACK=28` 堆叠重试（最多 6 次）。
3. 左右两侧候选按 `(交叉者计数, 距中线距离)` 评分选优，登记占用 `(ch, top, bot)`。
4. 无阻挡 → `BackBow` 侧向 U 形贝塞尔（本就安全）。

### 12.7 边间避让（`used_channels` + `used_trunks`）

- **绕行通道**：全局 `used_channels: Vec<(ch, top, bot)>` 登记已占用绕行通道坐标与跨度。后规划边不得与已占用通道同坐标且跨度重叠，否则两条边画在同一条线上。评估分两轮：**先严格**（节点 + 边间避让都满足），全部被拒时**放宽**（节点避让优先于边间避让）。
- **正交主干**（阶段 0.6）：`orthogonal_route` 用 `used_trunks: Vec<(trunk, s0, s1)>` 登记已占用正交主干；候选主干按 `(节点冲突数, 是否占用主干, |偏移|)` 字典序评分，节点避让优先于边间避让，`trunk` 不穿节点时才登记占用。

### 12.8 几何工具

- **`rounded_polyline`**：拐点用二次贝塞尔升阶为三次平滑过渡，`radius` 不超过相邻段一半，用于通道绕行路径。
- **`points_to_route`**：折线点序列 → 路由段，跳过重复点、合并共线段。
- **`sample_path`**：贝塞尔按 n 等分采样为折线，供碰撞检测。
